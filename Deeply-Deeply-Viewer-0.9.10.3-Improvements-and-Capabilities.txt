5. BUILT-IN BROWSER
======================================================================

The build includes a browser integrated into the viewer, based on the web
component already present in the viewer architecture.

Main features:

- opening web pages inside the viewer;
- address bar;
- back and forward navigation;
- stop and reload controls;
- loading progress;
- HTTPS connection indication;
- option to open a page in the system browser;
- configurable home page;
- support for HTTP and HTTPS links;
- handling of compatible SLURL and app links inside the viewer.

Browser behavior can be configured through these preferences:

- SystemForAll: use the system browser for every link;
- BuiltInForSecondLife: use the built-in browser for virtual-world links;
- BuiltInForAll: force the built-in browser for all compatible web links.

For security reasons, unsupported schemes such as javascript:, data:, and
other non-web links are refused. Users should verify pages before entering
credentials or personal information.

6. OPTIONAL CHAT LOG SHARING
======================================================================

The build retains optional transcript sharing with folders compatible with
Firestorm.

- Bidirectional access to supported private and group conversations.
- Separate folders for custom grids.
- No transcript changes when sharing is disabled.
- The feature is optional and must be enabled deliberately by the user.

Chat logs may contain personal information. Review their contents and remove
sensitive data before sharing them.

======================================================================
7. PER-AVATAR CONTROLS
======================================================================

The build adds persistent and separate controls for events from a specific
avatar.

Teleport:

- persistent rejection of teleport offers from a selected avatar;
- rejection is applied before the offer is accepted.

Conference chat:

- persistent rejection of conference chat invitations from a selected avatar;
- the invitation is rejected before the conversation session is opened;
- this control is independent from the avatar's total block.

The controls remain separate:

- total block;
- voice mute;
- teleport rejection;
- conference chat rejection.

======================================================================
8. ADAPTIVE GRAPHICS AND OVERLOAD PROTECTION
======================================================================

Graphics monitoring can gradually reduce the preset when sustained hardware
pressure is detected, avoiding an immediate jump to minimum quality or a
crash.

Reduction sequence:

Deluxe -> High -> Medium -> Low -> Potato

The monitor considers:

- process memory usage;
- frame times;
- GPU stalls and pressure;
- consecutive overload samples.

Behavior:

- quality is reduced one level at a time;
- consecutive samples are required to avoid reacting to isolated spikes;
- a cooldown prevents changes that are too close together;
- Custom profiles are not changed automatically;
- emergency safe graphics remains separate for serious graphics-device
  failures.

This feature reduces the risk of instability, but cannot guarantee that every
hardware, driver, or operating-system problem will be avoided.

======================================================================
9. REPORT AND ISSUE SYSTEM
======================================================================

The report system provides several delivery modes:

- save the report locally;
- open a GitHub issue draft in the browser;
- submit to the Deeply Deeply Viewer GitHub issue tracker after explicit
  authorization;
- copy the report to the clipboard;
- open the official Linden Lab form for review and manual submission.

The Linden Lab path is deliberately manual:

- the viewer prepares and copies the report content;
- the user reviews the information;
- the user pastes the content into the official form;
- the user decides whether to submit the report.

The build does not use undocumented Linden Lab endpoints and does not
automatically send data to Linden Lab.

Data such as position, avatar information, logs, diagnostics, and screenshots
is optional. Review the content before publishing it online.

======================================================================
10. PRIVACY AND SECURITY
======================================================================

- Online reports require an explicit user action.
- Diagnostic data and screenshots are not mandatory.
- Chat logs may contain personal information and must be reviewed before
  sharing.
- The built-in browser refuses unsafe or unsupported web schemes.
- The built-in browser uses a separate temporary session cache; the web
  session ends when the window closes, the user logs out, or the viewer
  restarts.
- The system browser can be selected by the user when needed.
